# 数据库迁移脚本目录

后端启动时会自动执行本目录下**尚未执行过**的 `.sql` 脚本（用 `schema_migrations` 表记录已执行的脚本，不会重复执行）。

## 命名约定

文件名必须 `V{序号}__{描述}.sql`，序号用递增整数，例如：

```
V1__add_merchant_email.sql
V2__add_dish_sales.sql
V3__add_coupon_table.sql
```

## 小组协作流程

1. 谁改了数据库结构，就在本目录加一个 `V{下一个序号}__描述.sql`，里面写增量 SQL（加字段、建表、加索引等，尽量幂等）。
2. 提交代码。
3. 其他组员拉代码 → 重启后端 → 结构自动同步，不用再手动跑 SQL。

## 注意

- 脚本按序号顺序执行，一旦执行过就不会改动（即使后来修改了文件内容，也只记录不重跑）。所以已提交的迁移脚本**不要改**，需要修正就加一个新脚本。
- 脚本执行失败会中断后端启动（防止带着不一致的库继续运行），修复脚本后重启即可。
- 首次建库仍需要跑 `db/schema.sql`（全量建表）+ `db/init-data.sql`（演示数据），之后的增量变更交给本目录自动同步。
