# 大模型客服：接入与查询的实现细节

> 本文对应 `canteen-backend/src/main/java/com/qmz/canteen/agent/` 下的 5 个类，行号可直接在 IDEA 里跳转。
> 分两部分：**如何接入**（从空项目到跑通）、**如何查询**（一次提问怎么变成查库 + 回答）。

---

# 第一部分：模型如何接入

## 1.1 前置：拿 Key，确认协议

- 平台：智谱开放平台（`https://open.bigmodel.cn`）→ 控制台创建 API Key。
- 关键判断：**它提供 OpenAI 兼容接口**（`/api/paas/v4/chat/completions`），所以能按标准协议写，不依赖厂商 SDK。
- 用 `curl` 先验证一次（改代码前必须先确认 key + 模型名可用）：
```bash
curl https://open.bigmodel.cn/api/paas/v4/chat/completions \
  -H "Authorization: Bearer $CANTEEN_AGENT_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"glm-5.3-flash","messages":[{"role":"user","content":"你好"}],"max_tokens":50}'
```
> 答辩时可强调：**先验证再接**，避免代码写完发现 key 或模型名不对。

## 1.2 第一步：配置项（application.yml）

```yaml
canteen:
  agent:
    enabled: true                                  # 总开关
    base-url: https://open.bigmodel.cn/api/paas/v4
    api-key: ${CANTEEN_AGENT_KEY:}                 # 环境变量优先（默认值务必留空！）
    model: glm-5.3-flash
    timeout-ms: 30000
    max-tool-rounds: 3
    history-limit: 8
    temperature: 0.2
    max-tokens: 800
    fallback-to-rule: true
    enable-for-admin: true
```

对应绑定类 `AgentProperties.java`（47 行）：

要点：所有字段都有 Java 默认值，`application.yml` 不配也能跑（用默认模型）；`api-key` 为空时上层会判定不可用并降级。

## 1.3 第二步：协议 DTO（LlmProtocol.java，74 行）

不引第三方 SDK，自己定义最小的请求/响应结构：

```java
public static class ChatRequest {
    private String model;
    private List<Map<String, Object>> messages;   // [{role, content, tool_calls, tool_call_id}]
    private List<Map<String, Object>> tools;      // 工具定义（JSON Schema）
    private String toolChoice = "auto";           // auto | required
    private double temperature = 0.2;
    private int maxTokens = 800;
    private boolean stream = false;
}

public static class Choice {
    private Integer index;
    private Message message;
    private String finishReason;                  // stop | tool_calls
}

public static class Message {
    private String role;
    private String content;
    private List<ToolCall> toolCalls;
    private String reasoningContent;              // 智谱思考链：只接收不回传
}
```

三个实现细节（面试/答辩常问）：
1. **字段名自动映射**：Jackson 配 `PropertyNamingStrategies.SNAKE_CASE`，Java 的 `toolCalls` ↔ JSON 的 `tool_calls`、`finishReason` ↔ `finish_reason`，不用手动写 `@JsonProperty`。
2. **`FAIL_ON_UNKNOWN_PROPERTIES = false`**：厂商多返回字段不会炸（换模型兼容性关键）。
3. **`reasoningContent` 只接收不读取**：GLM 会返回思维链；回传 assistant 消息时**不能带它**，否则部分网关直接拒绝请求。

## 1.4 第三步：通信层（LlmClient.java，257 行）

只做"发请求 + 解析 JSON"，不含业务逻辑。核心是两套方法：

### （1）非流式 `chat()` —— 用于工具决策轮
```java
HttpRequest.newBuilder()
    .uri(URI.create(trimSlash(props.getBaseUrl()) + "/chat/completions"))
    .timeout(Duration.ofMillis(props.getTimeoutMs()))
    .header("Authorization", "Bearer " + props.getApiKey())
    .header("Content-Type", "application/json; charset=utf-8")
    .POST(HttpRequest.BodyPublishers.ofString(json, StandardCharsets.UTF_8))
    .build();
```
- 用 **JDK 自带 `java.net.http.HttpClient`**，不引 OkHttp/WebClient，少一个依赖。
- `HttpClient` **懒加载 + 双重检查 + volatile 复用**（连接池复用，别每次 new）。
- 连接超时取 `min(timeoutMs, 8000)`：连接阶段不该等 30 秒。
- 异常统一包成 `LlmException`，上层只认这一种异常 → 降级逻辑简单。

错误处理做了三层：
```java
if (response.statusCode() != 200) throw new LlmException("模型返回 HTTP " + code + "：" + body);
JsonNode root = MAPPER.readTree(body);
if (root.has("error") && !root.get("error").isNull())   // 兼容网关把错误包在 200 里
    throw new LlmException("模型返回错误：" + ...);
if (parsed.getChoices() == null || parsed.getChoices().isEmpty())
    throw new LlmException("模型未返回任何候选结果");
```

### （2）流式 `chatStream()` —— 用于最终回答
```java
request.setStream(true);
// 请求头多一个：Accept: text/event-stream
HttpResponse<InputStream> response = client().send(httpRequest, BodyHandlers.ofInputStream());

while ((line = reader.readLine()) != null) {
    if (!line.startsWith("data:")) continue;
    String payload = line.substring(5).trim();
    if ("[DONE]".equals(payload)) break;
    String delta = extractDelta(payload);
    if (delta != null && !delta.isEmpty()) {
        full.append(delta);
        onDelta.accept(delta);      // 每片增量立刻回调 → 推给前端
    }
}
```
- **手工解析 SSE**：按行读、只认 `data:` 前缀、`[DONE]` 结束。
- 记录 `首片耗时 / 分片数 / 总耗时`，方便调优（日志里能看到"首片 1.2s、共 42 片"）。
- **中断保护**：流读到一半断了，已收到的内容仍然返回，不整段丢弃。
- 空响应抛异常 → 触发降级。

### （3）分工原则（重要）
| 阶段 | 用哪个 | 为什么 |
|---|---|---|
| 工具决策轮 | `chat()` 非流式 | 要完整解析 `tool_calls`，流式反而复杂且无收益 |
| 最终回答 | `chatStream()` 流式 | 用户要看到逐字输出，缓解 8 秒等待 |

## 1.5 第四步：接入口（ChatServiceImpl + ChatStreamController）

**降级判定**在 `ChatServiceImpl.tryAgentStream()`：
```java
if (!agentProperties.isEnabled() || question.isEmpty()) return null;       // 关了 → 走规则
if (!agentProperties.isEnableForAdmin() && UserContext.isAdmin()) return null;
try {
    return toAnswer(orchestrator.chatStream(question, history, onDelta));
} catch (LlmClient.LlmException e) {
    if (!agentProperties.isFallbackToRule()) { /* 返回"助手繁忙" */ }
    return null;                                        // null = 交给规则引擎
}
```

**SSE 接口**在 `ChatStreamController`：
```java
@PostMapping(value = "/ask/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public SseEmitter askStream(@RequestBody @Valid ChatRequest request)
```
为什么单独建类：`text/event-stream` 没有对应的 `HttpMessageConverter`，全局异常处理器包装 JSON 时会二次抛 `HttpMessageNotWritableException` 把真实错误盖掉 → 这里用**类级 `@ExceptionHandler`** 兜住。

事件契约：
```
event: delta   data: {"text":"正在查询食堂数据…"}
event: delta   data: {"text":"宫保鸡丁"}
event: done    data: {"answer":{...完整 ChatAnswerVO，含卡片...}}
```

# 第二部分：查询是怎么发生的

## 2.1 一次提问的完整时序（7 步）

```
① 前端 POST /api/chat/ask/stream  {question, history[]}
② ChatServiceImpl → tryAgentStream → AgentOrchestrator.chatInternal
③ 组 messages：[system prompt] + [历史 ≤8 条] + [本轮 user]
④ 第 1 次请求模型（带 7 个 tools，tool_choice=auto）
     ├─ 返回 tool_calls → ⑤
     └─ 返回文本   → 若首轮且 needsData → 强制 tool_choice=required 重试
⑤ appendAssistantAndRunTools：
     把 assistant 的 tool_calls 原样放回 messages
     → 逐个执行 AgentTools.execute() 查库
     → 每个结果包成 {role:"tool", tool_call_id, content:JSON} 追加
⑥ summarize：再请求一次模型（**不带 tools**），只让它读结果总结 → 流式输出
⑦ 结果同时返回给上层：text + toolResults（卡片数据取自这里，不取自模型）
```

## 2.2 组 messages（含安全细节）

```java
messages.add(Map.of("role", "system", "content", SYSTEM_PROMPT));
int from = Math.max(0, history.size() - props.getHistoryLimit());   // 只取最近 8 条
for (...) {
    if (!"user".equals(role) && !"assistant".equals(role)) continue;  // 丢弃伪造的 system
    messages.add(Map.of("role", role, "content", content));
}
messages.add(Map.of("role", "user", "content", question));
```
> **安全点**：历史由客户端上传，必须白名单只收 `user/assistant`，否则攻击者塞一条 `role=system` 就能提权改指令。这个细节被问到很加分。

## 2.3 工具是怎么定义的（JSON Schema）

`AgentTools.definitions()` 返回 7 个工具，每个都是标准 Function Calling 结构：
```java
tool("search_dishes", "按菜名/分类/描述搜菜品，返回价格、评分、窗口",
     Map.of("keyword", Map.of("type","string","description","菜品名称或关键词，例如 宫保鸡丁"),
            "limit",   Map.of("type","integer","description","返回条数，默认 5，最大 8")),
     List.of("keyword"))
```
| 工具 | 何时被调用 |
|---|---|
| `search_dishes` | "宫保鸡丁多少钱" |
| `list_stalls` | "有几个窗口" |
| `list_stall_dishes` | "川味小炒有什么招牌菜" |
| `get_rankings` | "今天有什么推荐 / 哪些菜避雷" |
| `search_faq` | "怎么投诉 / 评价能改吗" |
| `list_notices` | "最近有什么公告" |
| `get_overview` | "食堂整体怎么样" |

> 关键：**工具描述就是给模型看的"说明书"**，写得越具体（含示例），模型选得越准。

## 2.4 工具怎么执行（查库的真实代码）

`AgentTools.execute()` 是个 switch 分发：
```java
return switch (name) {
    case "search_dishes"      -> searchDishes(str(args.get("keyword")), intArg(args.get("limit"), 5));
    case "list_stalls"        -> listStalls(str(args.get("keyword")));
    case "list_stall_dishes"  -> listStallDishes(str(args.get("stallName")), boolArg(args.get("onlyFeatured")));
    case "get_rankings"       -> rankings(str(args.get("type")), intArg(args.get("limit"), 5));
    case "search_faq"         -> searchFaq(str(args.get("keyword")));
    case "list_notices"       -> listNotices(intArg(args.get("limit"), 3));
    case "get_overview"       -> overview();
    default -> Map.of("error", "未知工具：" + name);
};
```

以 `searchDishes()` 为例（真实查询逻辑）：
```java
LambdaQueryWrapper<Dish> wrapper = new LambdaQueryWrapper<Dish>()
        .eq(Dish::getStatus, 1)                     // 只查在售
        .orderByDesc(Dish::getFeatured)             // 招牌菜优先
        .orderByDesc(Dish::getId);
if (StringUtils.hasText(kw)) {
    wrapper.and(w -> w.like(Dish::getName, kw)
            .or().like(Dish::getCategory, kw)
            .or().like(Dish::getDescription, kw));
}
List<Dish> dishes = dishMapper.selectList(wrapper.last("LIMIT " + size));
if (dishes.isEmpty() && StringUtils.hasText(kw)) dishes = fuzzyFromAll(kw, size);  // 宽松兜底
```
- **直接查库，不走任何内存索引/缓存** → 新增菜品立即可见（这就是"新数据识别"能力的来源）。
- 评分、窗口号再用 `statsMapper.selectDishBrief()` 一次性补齐（避免 N+1）。
- `limit` 用 `clamp(limit, 1, MAX_ITEMS)` 夹紧，防模型传 999。

## 2.5 首轮"只说话不查库"的兜底（最关键的工程细节）

小模型带多轮历史时有 **30%~50%** 概率跳过工具直接编（实测把 12 元的宫保鸡丁答成 8 元）。调提示词治不好，所以在协议层强制：
```java
if (round == 0 && calledTools.isEmpty() && needsData(question)) {
    LlmProtocol.ChatResponse forced = chatWithRequired(messages, toolDefs);  // tool_choice=required
    List<ToolCall> forcedCalls = forced.getChoices().get(0).getMessage().getToolCalls();
    if (forcedCalls != null && !forcedCalls.isEmpty()) {
        appendAssistantAndRunTools(...);          // 查库
        return summarize(...);                     // 直接收敛
    }
}
```
`needsData(question)` 判断问题是否涉及价格/评分/菜品/档口等，避免把"你好"也强制查库。

## 2.6 工具结果回填 + 一个实战补丁

```java
for (ToolCall call : calls) {
    Map<String, Object> args = parseArgs(call.getFunction().getArguments());   // 容错解析
    Object result = tools.execute(call.getFunction().getName(), args);

    // 补丁：模型常把「验证用新菜」截成「新菜」，或误判成榜单工具
    Object byRaw = tools.searchByRawQuestion(rawQuestion, 5);
    if (!isEmptyDishResult(byRaw)) {
        result = byRaw;                                  // 以原始提问的精确命中为准
        toolResults.put("search_dishes", byRaw);
    }

    toolResults.put(name, result);                       // 卡片数据来源
    String payload = JSON.writeValueAsString(result);
    if (payload.length() > 6000) payload = payload.substring(0, 6000) + "...(已截断)";  // 控 token

    messages.add(Map.of("role","tool", "tool_call_id", call.getId(), "content", payload));
}
```
三个要点：
1. **结果必须原样回填**，否则下一轮模型看不到数据会瞎编；
2. **`tool_call_id` 必须对应**，否则网关报错；
3. **`toolResults` 单独留一份给前端做卡片**——卡片里的价格评分来自这里，不是模型文本。

## 2.7 收敛阶段（summarize）：从协议层禁止再调工具

```java
private AgentResult summarize(...) {
    finalMessages.add(Map.of("role","user","content", SUMMARIZE_INSTRUCTION));
    LlmProtocol.ChatRequest req = new LlmProtocol.ChatRequest();
    req.setMessages(finalMessages);
    // 注意：不 setTools(...) —— 不给 tools，模型只能输出文本
    if (onDelta != null) { llmClient.chatStream(req, delta -> onDelta.accept(sanitize(delta))); }
}
```
- 不给 `tools` 字段 = 协议层强制它只能说话，比"提示词要求别调工具"可靠。
- 这里才切流式：工具轮已经花掉 3~6 秒，最后这步必须让用户看到字在出。
- `sanitize()` 清洗 GLM 爱加的 Markdown/emoji（前端按纯文本渲染）。

## 2.8 为什么卡片数据不取模型输出

```java
answer.setItems(cardBuilder.build(result.toolResults()));   // 工具原始结果
answer.setText(result.text());                              // 模型语言
```
模型只负责"说人话"，数字、菜名、窗口、评分全部来自数据库 → **从架构上消除幻觉**。这是整套设计里最值得讲的一句话。

# 第三部分：如果老师追问"怎么做扩展"

## 3.1 加一个新工具要几步？（4 步）
1. `AgentTools.definitions()` 里加一条 `tool(name, description, params, required)`；
2. `AgentTools.execute()` 的 switch 里加一个 case；
3. 写私有方法实现查询（用 Mapper，别拼 SQL 字符串）；
4. 重启后即可用，**不需要改 prompt、不需要改编排逻辑**。

> 这就是工具化的好处：能力扩展 = 加函数，不是改模型。

## 3.2 换模型要几步？（1 步）
改 `application.yml` 的 `base-url` + `model`（+ 可能调 `timeout-ms`），**零代码改动**——因为走 OpenAI 兼容协议。

## 3.3 怎么调试这套链路？
- `log.info("Agent 第 {} 轮：finish={} toolCalls={}")` 看模型有没有调工具；
- `log.debug` 打印工具参数与结果（仅前 400 字）；
- `LlmClient` 日志有 `首片/总耗时/分片数`，延迟问题一眼定位；
- 出问题先看是"没调工具"（改 prompt/强制 required）还是"查不到"（改工具/SQL）。
